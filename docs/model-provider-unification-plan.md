# 模型供应统一与动态目录方案

日期：2026-09-10。状态：已完成当前代码、331 条目录元数据及重点协议文档调查；尚未进行带密钥的真实调用，也未实施供应层重构。

详细请求/响应矩阵、文档矛盾及样例回放结果见[协议调查记录](model-provider-protocol-audit.md)。本次结构化读取 88 份 Apifox 接口文档，并对重点链路核对请求参数、响应和任务查询；不是对 331 个模型逐个生成实测。

## 1. 结论与目标

可行。推荐把目前按供应商品牌和模型名分散维护的逻辑，收敛为 **连接配置、模型目录、协议适配器** 三部分。

目标是：站点新增采用已支持协议、且能力描述完整的模型后，项目自动发现，通过配置启用即可使用，不再为每个模型修改前后端代码。全新协议、响应结构或交互能力仍需要适配开发，不能承诺拉取一次目录就自动支持全部模型。

### 已确认的模型保留策略

用户已选择：**文本、图片、视频、配音每类精选 5–15 个主力模型，默认按模型发布时间从新到旧排序；其余隐藏，需要时再启用。** 本次重构不是全模型兼容工程，也不为已经不需要的旧型号恢复调用能力。

- 每类精选目录以 5–15 个为目标，上限 15 个；同一型号的文生图/编辑、首帧/首尾帧等操作不重复占名额。依据实际用途、效果、稳定性、成本和站点可用性筛选；不靠重复别名或落后型号凑数。最终型号清单另行结合验证结果确定。
- 排序依据核实的模型发布时间，降序展示。pricing 中的 updated_time 是元数据更新时间，sort_num 是站点展示顺序，两者都不能直接当作模型发布时间；发布日期或日期后缀的含义需要核实，缺失日期的型号排后并标记未核实，不编造日期。该发布时间信息由可更新配置补充，不硬编码到前端。
- 5–15 个是每类精选目录的目标范围，不是所有用户必然可调用的数量。某类已验证型号不足 5 个，或某密钥可用范围过滤后不足 5 个，就显示实际数量。配音仅计入文本转语音，不用转录、实时语音或音色设计填充。
- 远端目录负责发现，精选配置负责展示和启用。同步到的新模型默认隐藏；具备已验证协议配置后，修改精选配置即可启用，无需改业务代码或重新构建。
- 区分“已启用”“已隐藏”“待适配”“不可用”。隐藏型号仍可从完整目录中查到，恢复展示前重新检查协议、能力和密钥权限；不把未适配型号一键显示成可调用。
- 明确弃用或已被主力型号替代、没有保留价值的型号退出新建任务选择。已完成作品和历史记录保留原模型名；再次生成时选择当前启用模型，不静默改写历史参数。
- 老模型专属适配器在没有保留模型、其他连接或未完成任务依赖后删除。共享协议即使服务过旧模型，只要主力模型仍使用就保留。
- 不为“也许有旧任务”开发永久兼容层。实施前检查实际未完成任务；只有存在时才保留必要的临时查询/下载路径，任务结束后移除。

331 个目录条目、21 个 Responses-only 型号和协议调查矩阵都是调查范围，不是必须上线或长期维护的名单。

**经过进一步调查，不能只按“一个模型绑定一个接口”设计。** 同一模型的文生图、编辑、首帧、首尾帧、多参考生成可以使用不同请求；同一路径也可能返回不同封装。应按“连接 + 模型 + 操作”选择一套受控协议配置，其中同时确定请求编码、结果解码、查询及下载方式。

本方案假设保留现有用户密钥、第三方兼容地址和硅基流动接入；AICON 是推荐连接，并非将全部旧连接强制改为 AICON。模型厂商（Google、OpenAI 等）只作为目录展示信息，不能用于推断密钥应发送到哪个站点。

本方案的实施版本已在 `codex/model-provider-unification` 完成代码接入，具体落地范围与边界以[接入指南](model-provider-configuration.md)为准。以下保留最初的调查和设计取舍，不代表所有候选功能都已实现。

## 2. 站点接口核实

公开读取来源：

- [模型广场 JSON](https://api.aicon-studio.com/api/pricing)
- [API 文档索引](https://dcsynw64g3.apifox.cn/llms.txt)
- [统一格式创建视频](https://dcsynw64g3.apifox.cn/513530042e0)
- [统一格式查询视频](https://dcsynw64g3.apifox.cn/513530044e0)
- [OpenAI 格式创建视频](https://dcsynw64g3.apifox.cn/513530046e0)
- [OpenAI 格式查询视频](https://dcsynw64g3.apifox.cn/513530047e0)
- [Gemini 图像生成](https://dcsynw64g3.apifox.cn/513530040e0)

本次 `/api/pricing` 无需令牌即可读取，返回 `success=true`、331 条模型记录、31 条厂商记录，以及顶层 `pricing_version`。数量是本次快照，不应写进程序常量。

| 数据 | 可以支持什么 | 不能由此保证什么 |
| --- | --- | --- |
| `model_name`、`description`、`vendor_id`、`vendors` | 模型标识、介绍、厂商展示 | 对当前密钥可用 |
| `tags`、`model_type` | 分类提示 | 严格的输入输出能力约束 |
| `supported_endpoint_types`、`supported_endpoint` | 已知协议的匹配线索 | 完整请求、参数、查询及结果契约 |
| `enable_groups`、`usable_group` | 站点分组信息 | 当前 API Key 的实际权限 |
| 价格字段、`billing_mode`、`pricing_version` | 价格信息展示与变化检测 | 单一公式计算所有模型的最终费用 |

已经观察到的元数据缺口：

1. 14 条模型缺少 `model_type`，其余分类混有“文本”“对话”“chat”“音视频”等值。
2. `wan3.0-video`、`tts-1`、`gpt-4o-mini-tts` 标记的接口类型均为 `openai`，其全局映射为 `/v1/chat/completions`。单凭这一字段无法决定视频生成或语音合成的调用方式。
3. `openai-video` 被模型引用，却没有对应的顶层路径定义；有的 `path` 是序列化 JSON 字符串，另有 `path="gemini"`。
4. 顶层“查询视频任务”标记为 POST，但上述具体视频查询文档为 GET。因此不能直接执行目录下发的 method/path。
5. 没有统一的生成时长、宽高比、分辨率、参考图数量、首尾帧、音色、结构化输出等机器可校验能力字段。自然语言介绍中的限制也不能代替这些字段。
6. 当前 `custom` 写死的五个 `veo3.1*` 视频模型名均未出现在本次目录快照中。不能据此认定原调用失效，也不能把旧名自动改成某个相似的新名；需要用授权令牌确认可用性与别名关系。
7. 有 21 个模型仅声明 `openai-response`，不能全部发到 Chat Completions。Responses 作为主力文本候选的必要协议评估，但不因此保留这 21 个型号；最终适配范围由精选型号决定。
8. `text-embedding-3-large` 被归为“文本”，`gpt-4-vision-compatible` 被归为“图像”但标签为识图。类型标签不能直接等同于“能生成文本/图片”。
9. 多份 Apifox 响应 Schema/示例明显错配：模型列表、图片生成、Responses 页面出现聊天示例。文档可以支持人工制定协议配置，但目前不能直接作为自动生成适配器的可信完整契约。

无令牌读取 `/v1/models` 得到 401，确认该路径需要认证；尚未验证有效令牌下的返回字段，以及是否严格反映令牌模型限制、分组与可调用范围。没有进行任何收费生成调用。

## 3. 当前代码为何难以维护

| 位置 | 当前问题 | 收敛方向 |
| --- | --- | --- |
| `backend/src/services/api_key.py:get_models` | custom/OpenAI/DeepSeek/Google 为静态名单；硅基流动已有动态拉取，但分类失败会返回前 20 个模型 | 独立目录服务；无法分类时保留待配置状态，不混入错误用途 |
| `backend/src/api/schemas/api_key.py`、`provider/factory.py`、`frontend/src/services/apiKeys.js` | Schema 允许 9 种供应商，工厂实现 6 种且包含 Schema 不接受的 vectorengine；前端新增仅开放 2 种 | 连接预设来自一个后端注册表，校验和 UI 使用同一来源 |
| `provider/custom_provider.py` | OpenAI、Gemini、参考图下载、响应包装混在一个类中；按模型名含 gemini 路由 | 依据明确协议与能力选择适配器，共享素材准备逻辑 |
| `provider/openai_provider.py`、`deepseek_provider.py`、`volcengine_provider.py`、`siliconflow_provider.py` | 多个相似 SDK 封装，品牌与协议耦合 | 合并真正同协议的部分，保留真实参数差异 |
| `services/canvas.py` | 文本/图片走工厂，视频直接实例化 VectorEngineProvider；custom 空地址时视频回退 vectorengine 地址；参考图处理按 custom 判断 | 统一解析连接与能力，四种任务均通过同一个入口 |
| `services/transition_service.py` | 创建、恢复查询等位置直接依赖 VectorEngineProvider | 和 Canvas 共享视频提交、查询及结果解析适配器 |
| `provider/vector_engine_provider.py` | 提交用 `/v1/video/create`，查询用 `/v1/videos/{id}` | 文档存在两套协议，先验证历史任务兼容，再固定创建/查询组合 |
| `services/prompt.py`、`subtitle_service.py`、`dialogue_prompt_engine.py` | 业务内部按供应商选择或直接写死默认文本模型 | 一个统一的默认模型解析入口 |
| `frontend/src/components/studio/TransitionPanel.vue` | 初始值与失败兜底写死多个 Veo 名称 | 使用目录和明确默认配置，加载失败不能悄悄选别的模型 |
| `frontend/src/utils/canvasGenerationPayload.js` | 按 veo 前缀限制比例；其他参数为固定选项 | 前端读取能力，后端执行同一套校验 |
| `backend/src/assistant/agent_factory.py` | 助手请求固定携带 JSON 输出选项 | 助手模型还要筛选结构化输出能力，不能展示全部文本模型 |
| `api/v1/canvas.py:get_canvas_model_catalog`、`CanvasEditor.vue` | 所有密钥的名单合并去重，丢失密钥与模型的对应关系；默认密钥和默认模型分别取首项 | 模型列表按选中密钥与用途加载，默认值必须是一组合法组合 |
| `services/canvas.py:_extract_video_url`、`transition_service.py:sync_transition_video_status` | Canvas 不读 metadata.url/video.url，过渡同步只认 completed，均不能完整处理新文档样例 | 每个协议适配器输出相同任务结果，不在业务中堆响应字段猜测 |
| `services/audio.py`、`utils/image_utils.py`、`visual_identity_service.py` | 音频固定按 SDK 二进制写 MP3；图片存在多套解析且大多仅取第一张；部分链路只接受 URL | 图片/音频的格式、数量、下载及入库统一处理 |

另外，工厂使用 `kwargs.get("base_url", default)`，调用方显式传入 `None` 时不会应用默认值。统一连接解析应同时处理 None、空串和末尾斜杠；不能让不同任务自行回退到不同站点。

Gemini 实现目前会记录带查询密钥的完整 URL，参考图失败时继续生成，并截取前 5 张参考图。迁移该逻辑时应同步去掉密钥日志，按能力校验参考图上限，必要参考图读取失败应明确失败，不能静默丢失输入。

还有两个可由源码确定的历史问题需要在迁移入口时覆盖：DeepSeekProvider 未实现基类的抽象 generate_audio，无法按当前定义实例化；OpenAI/DeepSeek/Volcengine 类没有设置日志装饰器读取的 self.base_url。不能把“工厂有分支”计为供应商已正常支持。

## 4. 推荐结构

```text
API 密钥、站点地址 ──→ 连接解析
                         │
站点目录 ──→ 目录归一化 + 能力配置 + 密钥可用范围
                         │
          前端模型选择与参数表单
                         │
Canvas / Movie Studio / 提示词 / 语音 / Assistant
                         │
             统一生成入口与服务端校验
                         │
                按协议选择适配器
                         │
             统一结果 / 异步任务状态
```

### 4.1 连接配置

继续使用现有 APIKey 表保存密钥、归属和地址，不为模型目录复制密钥。新增模型不新增 Provider 类。

统一定义 AICON 默认站点根地址 `https://api.aicon-studio.com`，分别构造 `/api/pricing`、`/v1`、`/v1beta` 路径。现有保存的 `/v1` 地址通过连接解析处理，不使用全字符串 `replace("/v1", "")`。

仅在连接明确属于 AICON 时使用 AICON 目录；其他 custom 网关使用自己的模型发现方式或显式能力配置。不能拿 AICON 的模型名单去配任意第三方密钥。

### 4.2 动态目录

目录服务负责同步、归一化和缓存，APIKeyService 只负责密钥生命周期及访问控制。前端不直接携带用户密钥请求站点。

建议先沿用现有 Redis 缓存，按站点缓存公开目录，短 TTL 定时刷新或按需刷新，提供手动刷新入口，并保存最近成功快照。刷新失败返回旧快照与过期提示；从未成功时明确返回目录暂不可用，不回退到“前 20 个模型”。不必为了首版建立完整模型管理后台。

顶层版本用于识别目录变化；本地能力配置也需要版本，不能只依赖价格版本。

如果 `/v1/models` 经带密钥核实能表达令牌可用模型，再与目录取交集。权限缓存按用户、密钥记录、连接和凭据版本隔离，401/403、密钥停用或配置变更后失效。公开目录只能说明“站点收录”，不能说明“此密钥可用”；目录交集也不是额度、路由健康或调用成功保证。

### 4.3 能力配置与协议适配器

归一化模型至少包含：原始模型 ID、连接标识、显示信息、操作列表、每个操作的协议配置 ID、参数限制、可用状态、未就绪原因和目录版本。保留原始 model ID，避免模糊别名替换。协议配置绑定请求编码器、响应解码器和必要的查询/下载器；优先复用代码，但不能因为 URL 相同就认定参数语义相同。

以下是已调查的候选协议；最终只实现精选型号实际需要的部分。未选中的协议不占首版开发和验收范围：

| 协议 | 候选用途 | 若保留该协议，适配器必须处理 |
| --- | --- | --- |
| OpenAI Chat Completions | 文本、现有助手 | 请求参数与结构化输出支持、统一文本结果 |
| OpenAI Responses | 精选型号中需要 Responses 的文本模型 | messages/input 与 JSON 输出参数转换、output 内容块、流式事件、错误与不完整输出 |
| OpenAI Images | 文生图、图像编辑 | generations 与 edits 的区别，参考图编码，URL/base64 结果 |
| 兼容 Images 的 JSON 扩展 | Seedream、Qwen 等 | 图生图可能仍走 generations；image 字段、参数扩展及路径覆盖需要独立配置 |
| Gemini generateContent | 现有 Gemini 生图 | 内容 parts、比例和尺寸、参考图、inlineData 结果 |
| OpenAI Audio Speech | 现有语音合成 | model/voice/input、音频二进制与格式 |
| 统一 Video Create/Query | 仅在精选模型或实际未完成旧任务需要时保留 | JSON 提交、query 查询、状态与视频 URL；仅旧任务需要时不开放创建 |
| OpenAI Videos | 需要该协议的视频模型 | multipart 提交、任务轮询、下载内容的返回类型 |
| 网关 Video Generations | MiniMax H3、豆包相关路由候选 | duration、metadata；提交 id/task_id，查询 metadata.url；豆包与 MiniMax 的参考视频/音频字段位置不同 |
| Grok Video Generations | Grok 原生格式候选 | videos/generations、request_id、done、video.url；不能和单数 video/generations 混用 |
| Wan Video Synthesis | wan3.0-video | input/parameters、独立查询路径；成功返回契约仍需补证 |

上表不是全部必做清单，也不是现已支持名单。被选中的视频协议须先解决调查记录中的路径/别名/响应冲突，再启用。Gemini TTS 与 MiniMax TTS 只在精选配音需求涉及时适配；Midjourney 属于异步图像任务和后续动作，当前不纳入默认范围。Anthropic 原生、实时语音、嵌入/重排、音色设计和其他未选中的协议不主动建设，需要时再评估。

同一 endpoint 可以产生不同类型输出，所以必须结合明确用途与能力配置；不能仅用 endpoint 或模型名前缀判定。未知参数拒绝或明确提示，不静默丢弃；服务端校验为最终依据。

远端目录中的路径只用于已知映射匹配，不作为携带密钥请求任意 URL 的指令。适配器路径和 method 来自受控实现。

**要实现长期新增模型无需改项目代码，站点还需提供规范能力信息。** 推荐在站点增加一个带版本的能力清单（接口名待站点实现时确定），由本项目读取。它提供稳定协议 ID、输入输出用途、支持的比例/时长/分辨率/参考图上限等，且每个模型明确绑定协议配置。

如果暂时不能修改站点，项目可先用一个外部 JSON 配置文件补足能力缺口，支持重载、无需重新构建。这能消除散落分支，但仍需要人工维护配置，不能称为完全自动。避免首版开发任意请求模板或脚本执行引擎。

能力配置明确记录操作所需输入角色：普通参考图、首帧、尾帧、遮罩、参考视频、参考音频不能都压成 images 数组。UI 已有首尾分镜关系时，选择的操作必须支持对应语义；不支持时先提示用户选择其他操作或模型，不能静默退化成一般多图参考。

配置更新先校验完整性，再原子切换；保留上一份可用配置。未识别的协议 ID 不执行。Apifox 更新可用于人工审查的候选差异，不能让在线生成流程临时爬文档或让 LLM 动态猜请求体。

### 4.4 统一业务入口与前端

保留 `api_key_id + model` 的现有使用方式，内部统一执行：验证密钥归属与状态 → 解析连接 → 查模型与用途 → 校验参数 → 调用适配器 → 归一化结果。

图片/音频素材解析与存储仍复用现有服务；任务调度和业务生成历史保留，不把整个 Canvas 或电影工作流重写进 Provider。

目录接口需要返回对象而非仅 `List[str]`，才能驱动参数表单。迁移期增加详细目录接口，旧 `/{key_id}/models` 继续从同一目录投影字符串列表；前端调用方迁完后再删除旧响应适配。

模型选择、比例、时长、参考图等控件使用同一份能力信息。生成选择列表只显示精选配置启用、已适配且对所选密钥可用的模型，遵守每类最多 15 个及核实发布时间降序规则。显示排序不自动覆盖用户选择；默认模型来自用户/项目选择或连接级明确配置，不取远端排序第一项作为隐式默认。默认模型被隐藏或不可用时要求重新选择。历史记录仍显示原模型名，不能因此将隐藏模型重新加入新建任务选项。

异步任务提交时记录实际连接地址、模型 ID、适配器 ID/版本、目录/能力版本及供应商任务 ID，保留密钥记录引用，不复制明文密钥。恢复轮询时使用提交时的协议和目标地址，避免目录刷新或用户改地址后查错任务。凭据更换或撤销时明确提示恢复条件，不将新站点凭据自动发往旧地址。

### 4.5 统一请求、响应与错误契约

业务只提交所选操作、模型、密钥、提示词/消息、带角色的素材引用和参数。以已有数据类型表达，不把供应商请求 JSON 直接透传到业务接口。

| 内部结果 | 必要内容 | 下游行为 |
| --- | --- | --- |
| TextResult | text、finish_reason、usage、上游 request_id；需要时含 tool_calls | 业务不再读取 choices/output/candidates |
| MediaResult | 按顺序排列的媒体项，每项为 URL 或字节及 MIME/格式信息 | 统一素材服务下载/解码/校验/入库，再交给业务 object_key |
| JobResult | 上游任务 ID、归一状态、进度、错误、可用媒体或文件句柄 | 调度层按已保存协议轮询；适配器负责读原始字段 |
| StreamEvent | start、text_delta、usage、completed、error | 转成现有应用 SSE，前端不接触供应商事件格式 |

媒体字节/base64 不持久化进数据库响应 JSON；只保存必要的追踪信息、结果引用与脱敏诊断。原始用量可以附带保存，缺失值为未知，不能伪造零用量。

首版单图入口显式限制 n=1；在业务支持多结果历史之前，不开放多图输出选项再丢弃其余结果。语音必须按实际 MIME/编码处理：Gemini 文档样例是 PCM，MiniMax 有 hex/URL，不能一律将响应内容命名为 .mp3。

上游状态先转换为 queued/running/succeeded/failed/cancelled/unknown；应用成功必须同时满足素材已入库。上游完成但下载失败应继续结果恢复，不重新生成；查询超时不代表上游任务失败。未知状态或响应结构显式暴露协议错误，不能无限伪装 processing。

统一区分认证/权限、参数、限流、上游拒绝、网络、协议解析、素材下载错误。检查 HTTP 状态和业务错误体（例如 MiniMax base_resp），流式中途错误也要处理。查询与下载可按错误类型重试；创建超时且不知道是否已受理时记录提交结果不确定，不盲目重复 POST。现有图片 retry_with_backoff 实际对所有异常重试，应在迁移时替换为这一策略。

### 4.6 持久化与最小实现范围

- Canvas 已有 request_payload_json/result_payload_json，可增加服务端生成的 provider_context，保存解析后的执行配置；不信任前端自带的执行上下文。
- MovieShotTransition 目前保存 task_id、api_key_id、user_id，但未保存模型及协议快照。建议新增一个可空 JSON 执行上下文字段，通过增量迁移落地，无需另建万能生成任务表。
- 实施前检查是否存在未完成旧任务。确实存在且没有执行上下文时，使用已核实的临时查询配置；不能根据任务 ID 前缀猜协议。没有依赖时直接删除无用旧适配，不为历史上出现过的模型构建永久 legacy 层。
- 公共 HTTP、错误、媒体读取可复用；首版不重写全部任务队列、不建任意脚本式协议引擎、不建完整模型计费系统。

## 5. 清理与迁移步骤

1. **确定精选型号与实际依赖，集中连接配置。** 按四类用途各精选 5–15 个型号，记录发布时间依据并按新到旧排序，确定实际所需协议，列出隐藏型号与可删除适配器；检查未完成任务和仍需使用的连接。后端默认、两个密钥页面与 README 的新地址一致。历史 `custom` 不等于 AICON，不能批量覆盖所有自定义地址。
2. **引入目录与能力配置。** 接通 pricing，验证认证模型接口语义，按用途输出详细目录；旧模型列表从这里投影。验证新增模型、未知分类、字段异常、缓存过期及密钥隔离。
3. **迁移调用入口。** 只为精选模型实现需要的文本/助手/图片/语音/视频协议，将共享 Provider 合并。仅有实际依赖时保留短期旧入口；视频执行上下文迁移先于切换轮询。验证参数、素材、响应和异常行为，不能只验证返回 200。
4. **迁移全部模型选择页面。** 包括 Canvas、Assistant、Movie Studio 角色/场景/关键帧/过渡、普通视频任务和语音对话框。移除相关默认模型与名称猜测分支，保留用户已保存选择并提示不可用状态。
5. **删除旧实现。** 全量搜索调用点，确认已保留连接和实际未完成任务的依赖后，删除重复 Provider、无用旧协议、静态模型数组和过渡响应层。只有精选模型或仍使用的连接需要的真实差异才保留独立实现，不为隐藏的旧型号额外补齐兼容。

实施时以“精选主力模型可用、同协议型号可通过配置启用”为首版边界。完整目录后台同步，前台保持少量清晰选择；不以 331 个条目全部成功调用为目标。

## 6. 验收条件

- 在目录测试数据中新增采用已有协议与能力配置的模型，不修改业务代码，刷新后在完整目录可发现且默认隐藏；修改精选配置启用后才出现在生成选项并路由到正确适配器。
- 隐藏模型不再用于新建任务或自动默认值，历史作品和模型标识仍可查看；重新启用只需配置及能力/权限复核。无任何依赖的旧适配器已删除。
- 四类精选目录分别以 5–15 个为目标且最多 15 个；同模型多操作不重复计数。模型按核实发布时间降序、日期未知者排后；修改价格或介绍导致 updated_time 改变时，不能改变新旧排序。权限过滤后少于 5 个时不补入隐藏或不适配型号。
- 同一模型在 Canvas 和 Movie Studio 使用相同的连接、参数规则与结果解析；助手只出现满足其输出约束的模型。
- 未知端点、缺失用途、元数据冲突不会被误放入可生成列表；旧选择失效时不会悄悄替换模型。
- 目录故障不清空最近成功目录，认证失败不继续把旧权限标为可用，不泄露密钥或跨用户复用权限缓存。
- 参考图失败、数量超限、比例/时长不支持在生成前给出明确错误，不默默丢素材或改请求。
- 视频创建/查询/内容获取按同一协议配置执行；处理中、失败、超时、恢复和最终媒体入库均有覆盖。上游完成不等于应用素材已存储完成。
- 回归现有 CustomProvider、Canvas、Assistant 自动化，并为目录和协议契约补充有区分力的测试。
- 覆盖文档样例已发现的 metadata.url、video.url、request_id、succeeded/done，以及 Responses 流式错误和非消息输出项；验证图片 URL/base64、音频 PCM/hex 不会混淆。
- 同名模型在两个网关可绑定不同协议；切换密钥后列表、默认值、参数和权限同时更新，不能使用合并目录产生错误组合。
- 最后使用授权测试密钥按已支持协议做少量真实生成验证，包含文本、带参考图图片、语音、视频提交与查询。当前公开接口读取和文档比对不构成真实调用验收。

## 7. 尚需在实施中确认

1. **认证目录：** 有效密钥的 `/v1/models` 返回结构、分组与模型限制语义；当前只有无令牌 401 证据。
2. **能力清单：** 站点是否可提供按模型与操作绑定的规范配置；本仓库没有中转站实现，不能把站点改造写成已具备能力。
3. **历史视频（条件项）：** 只有实际存在未完成旧 Veo 任务或保留型号仍使用该协议时，才核实混合提交/查询兼容性；没有依赖则无需为旧 Veo 恢复支持。
4. **新视频：** sd-* 与文档中的 doubao-seedance-* 别名关系、Grok 单复数路径与参数版本、Wan 成功响应和查询路径矛盾。逐项见调查记录。
5. **响应样本：** GPT 图片/Responses 的真实返回、Gemini URL 扩展、Qwen 特殊路径、视频内容下载的 Content-Type。官方标准只能作为适配基线，不能证明中转站完全一致。

完成上述核实的最小资料是：可在后端安全使用的测试令牌（无需粘贴进文档），以及精选型号所需冲突协议的脱敏请求/成功响应/失败响应或网关维护者确认。历史 Veo 任务样本仅在确有未完成任务需恢复时提供。若使用真实生成获取样本，限定到精选型号所需协议的少量样本与费用范围，不向全部 331 个模型批量发送生成请求。
